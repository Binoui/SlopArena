# FightGuy move data report

> Generated by `tools/MoveDataReport` (2026-08-14 22:01 UTC) — runs the real shared sim.
> Method: each trajectory row launches a fresh grounded victim at the given % with the hitbox's authored
> knockback via `Simulation.ApplyKnockback`, then steps the sim until landing (cap 2400 ticks).
> No DI/SDI input. Hitstop is reported (in-code `ComputeHitstopTicks`, ADR-0019: min(12, dmg/3 + 6))
> but not simulated — flight starts at launch.
> Flight law (current sim): KV holds constant through hitstun (single integration per tick); at stun expiry KV is copied
> to V and the victim enters post-hitstun flight (ADR-0019 §6): gravity 14 m/s2 + horizontal friction 10 until
> landing or any action (jump/ability clears the regime). The AirTime float window no longer applies to launches.
> Combo matrix uses the no-travel bound: `TA = (IASA - trigger) [+ landing lag] [+ jump squat] + follow-up trigger`;
> `T` = TRUE combo (TA < stun at that %), `-` = not true. Travel and hitstop make reality harder than this bound.

> **adv** = on-hit frame advantage (ticks): `stun − (IASA − trigger)`; positive = the attacker acts before the
> victim leaves hitstun (can press/continue), negative = the victim recovers first. Hitstop freezes both, so it
> cancels out. Assumes the hit connects on the first active frame — later connects only improve advantage.
> **advL** (aerials): the landed follow-up pays `LandingLagTicks` on top (SHFFL-style); land inside an AC window
> (`≤ AC bef` / `≥ AC aft`) or chase with an aerial at IASA and the lag is skipped — the true landed number sits
> between `advL` and `adv`. Grounded moves land free (no lag), so `advL` is `—`.
